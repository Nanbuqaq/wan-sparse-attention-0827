# Bounded episode KV-version intervention — frozen development protocol

## Question, not an algorithm claim

The non-mutating native recache observer passed all four39-latent trajectory
identities. At the third switch, layer9 K/V relative L2 is0.3274/0.5640 and
layer19 is0.3496/0.6009. Identical visual frame coordinates do not imply identical
hidden KV: text condition AND the recomputed context change together. This is
expected mechanistically, not by itself a novel contribution or pure text effect.

Test whether storage version matters for a later memory intervention. Use the
locked native interactive1.3B pipeline and existing development toy revisit
schedule. The toy task has failed away-compliance in several baselines; positive
identity resemblance alone must not be scored as successful long-term memory.

## Frozen arms

1. `official_recache`: local12/sink1, no history archive.
2. `snapshot_pre_recache`: at the away boundary, keep the last6 completed raw KV
   frames BEFORE native recache, across all30 layers.
3. `snapshot_post_recache`: keep the same6 visual frame coordinates AFTER native
   recache under the away prompt/context.

At the declared return, both snapshot arms first perform the ordinary native
recache. They then replace6 non-sink local slots which will survive the next
3-frame cache roll. Most recent2 frames, sink and all cache endpoint counters
remain intact. Normal local-relative RoPE is applied to the replaced raw KV;
this is temporal repositioning, not original historical RoPE. All arms execute
the same local Attention size. Only one restore occurs:6/3/0 old frames survive
the successive3-frame chunks. No persistent reinjection.

The source frames are42–47 for the120-latent/477-pixel schedule, and6–11 for
the39-latent/153-pixel gate. Capture always precedes return; no future frames,
Dense teacher or mask enters the copied KV. But capture and restore boundaries
are PRIVILEGED experiment inputs, so this is NOT autonomous retrieval.

The diagnostic CPU snapshot has a2GiB cap and no full-history archive. Snapshot
D2H, H2D, hashes and preparation are included in the reported wall time. A speed
claim is not expected from these intervention runs. This bounded probe does not
retroactively make the general RAG CPU archive bounded.

## Gates and extension

- CPU tests: copied snapshot has no alias; budget/causality reject before writes;
  only surviving non-sink slots change, source values and cache endpoints persist.
- Real GPU39: all branches run, finite outputs, exactly identical noise and all
  pre-return latents. Recheck baseline against previous native official39 output.
- Only after that,120-latent/477-pixel development two seeds20260909/20260910,
  all three arms per seed, frozen before reviewing any version intervention.
- Review own reveal identity, away compliance, first return, late return, and
  timing. Pre-versus-post compares version AND context of construction, not text
  in isolation. Neither arm is promoted on a single seed or resemblance alone.
- If both fail to establish a stable version effect, preserve the negative and
  do not expand this diagnostic into an engineered online method this sprint.
