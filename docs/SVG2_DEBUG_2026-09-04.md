# SVG2 short-video debug: Top-p versus exact-budget selection

Date: 2026-09-04
Status: complete; four-cell audit passed.

## Conclusion

The short-video collapse is primarily caused by replacing SVG2's size-weighted
Top-p selection with a globally calibrated exact-25% pair budget. It is not
primarily caused by the Dense guard, the varlen backend, RoPE placement, or a
K/V permutation mismatch.

On the same `gymnast_ribbon` prompt and seed 9001, all four causal cells use the
`varlen_triton` backend. Top-p without any Dense guard preserves the gymnast,
motion, and ribbon. Exact-25% still collapses after adding ten Dense denoising
steps. The guard improves fidelity-to-Dense metrics but does not restore
acceptable absolute video quality.

This is a Wan-14B/720p upstream parameter-and-policy transfer to
Wan-1.3B/480p, not a complete paper reproduction. The upstream 40-layer model
maps a 3% layer guard to one layer, while the 30-layer 1.3B model maps it to
zero layers under the same floor rule.

## Source comparison

The pinned Sparse-VideoGen revision is
`f89aedaf169ac2ae5b186bda674e53c3dc08c476`.

The following core behaviors already match the upstream Wan SVG2/SAP path and
were not changed in this debug:

- Q and K are independently clustered with Euclidean K-means after RoPE.
- centroid attention is weighted by K-cluster size before Top-p selection;
- K and V use the same semantic permutation, and Q output is inverse-permuted;
- selected attention executes original Q/K/V rather than centroid V.

The historical `svg2_varlen` experiment instead calibrated Top-p-like scores to
an exact 25% token-pair budget with `min_k_ratio=0` and disabled the upstream
Dense guard. That variant is retained as a useful exact-budget ablation, but it
must not be presented as the upstream SVG2 policy.

All four videos have 81/81 decoded frames, matching SHA-256 records, zero
failed Attention calls, and zero Dense fallback calls. The guarded 50-step
cells used exactly 600 explicit Dense and 2400 sparse calls; the unguarded cells
used 0 and 3000.

The exact guarded result is an especially important evaluation warning: its
relative PSNR rises to 22.24 dB even though the subject remains ghosted and the
ribbon becomes a horizontal red smear. Fidelity-to-Dense metrics do not replace
absolute visual review.

## Decision and stopping rule

The causal decision is `selection_exact_budget_is_primary_failure`:

- Top-p without guard passes, so the Dense guard is not necessary to avoid the
  observed collapse on this case.
- Exact-25% with guard fails, so the guard is not sufficient.
- The older fixed64 and varlen exact-budget failures support that the backend is
  not the sole cause.

No Koi video was added. Although Top-p without guard is visually valid and has
only 19.72% logical density, its 331.72-second generation time exceeds the
317.74-second guarded-reference ceiling. It therefore fails the frozen third-
video gate and is not an end-to-end system win. No expanded 12-point QKV study
was needed because the four-cell outcome is unambiguous.

## LongLive implications

- Do not force a Top-p route into a uniform exact-pair target without checking
  whether the repair removes high-probability cluster mass from important
  queries. Equal pair count is not an equivalent selection policy.
- Track logical pair density, scheduled/padded density, unique KV transfer, and
  end-to-end time separately. The lower-density Top-p no-guard run was slower
  than the higher-density guarded run because variable-block routing and
  execution overhead dominate part of this path.
- A Dense early-step guard can improve fidelity and may reduce time when Dense
  SDPA replaces a slow sparse path, but it was not the primary quality fix here.
- Short-video SVG2 clusters post-RoPE full-video Q/K. LongLive archives
  unrotated history and applies relative RoPE after selection, so this ordering
  must not be copied mechanically across frames.
- Top-p quality alone does not bound the unique historical KV union or transfer;
  LongLive still needs an explicit transfer-bounded shared-pool constraint.
